# F5 — Botnet traffic (`botnet`)

Ticket E1-12 (SCRUM-113). Method: ADR-0003. Predicted visibility (`attack_families.yaml`):
mqtt no, flows yes, honeypot no.

## What it does

A compromised IoT device D sends botnet traffic to an external command-and-control host. F5
replays a fixed slice of a published Mirai capture — the first 10,000 packets of
`PCAP/Mirai-greeth_flood/Mirai-greeth_flood1.pcap` from CICIoT2023 [8] (GREeth flood: GRE-
encapsulated UDP floods). The slice is retargeted with `tcprewrite` so the source is D and the
destination is a fixed non-routable address (192.0.2.1, RFC 5737 TEST-NET-1, which no testbed
host answers), then replayed with `tcpreplay` from the attacker container at a fixed 200 pps
(~50 s). D is therefore the only testbed endpoint in the traffic (Annex C ASSUMPTION 5).

The capture slice is **not committed** (ADR-0003 does not redistribute derived captures):
`scenarios/botnet_manifest.yaml` records the dataset, file, packet range and SHA-256, and the
runner verifies the local slice's digest before replay (`BotnetManifestError` otherwise). The
slice is mounted read-only into the attacker container (`data/external` → `/slices`).

## Sources that received traces

Measured over two same-seed runs on `iot-cam-01`, 90 s episodes (`test_f5_run.py`, 2026-10-10):

| Source | Trace | Count per run |
|---|---|---|
| mqtt | no | 0 attack messages |
| flows | yes | 37 flows to the C2, dominated by one GRE flow of ~9,900 packets; ~9,955 packets total |
| honeypot | no | 0 events |

Observed visibility matches the predicted matrix. Both runs gave identical counts (37 flows,
9,955 packets).

## Retargeting notes

- `tcprewrite --srcipmap=0.0.0.0/0:<D> --dstipmap=0.0.0.0/0:<C2>` rewrites the outer IP header
  of every packet; the inner (encapsulated) addresses of the GRE/UDP flood are left as the
  dataset recorded them. Keying is by the outer IP (record §4.1 `subject_device`), so the
  bundle keys to D.
- Only the IP is rewritten, not the MAC: the replay is captured at the attacker's egress
  sidecar (ADR-0009) and `subject_device` uses the IP, so the source MAC does not affect keying.

## Repeatability

Raw counts over two same-seed runs are compared within the F5 tolerance in
`tests/attack_tolerance.yaml` (packets 0.05, flows 0.25). The replay is deterministic (a fixed
slice at a fixed rate), so both runs gave exactly 9,955 packets and 37 flows to the C2.
