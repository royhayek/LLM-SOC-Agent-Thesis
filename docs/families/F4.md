# F4 — SSH credential guessing (`ssh_brute_force`)

Ticket E1-11 (SCRUM-109). Method: ADR-0003. Predicted visibility (`attack_families.yaml`):
mqtt no, flows yes, honeypot yes. This is the walking-skeleton spike scenario (record §9).

## What it does

An external attacker host guesses SSH logins against the honeypot with THC-Hydra, over a fixed
username list (`scenarios/ssh_users.txt`, 3 users) and password list
(`scenarios/ssh_passwords.txt`, 8 passwords). Every user x password pair is tried once (no early
exit), at a fixed task count (`-t 4`). Hydra completes the SSH handshake, so Cowrie logs the
attempts. The attack runs in the `attacker` container and addresses the honeypot by IP. Bounded
by the lists, so it exits 0. Uses the attacker container and Cowrie-on-22 added by F3.

|---|---|---|

Observed visibility matches the predicted matrix. Both runs gave identical counts.

## Repeatability

Raw counts over two same-seed runs are compared within the F4 tolerance in
`tests/attack_tolerance.yaml` (flows 0.30, honeypot 0.20). Both runs gave 9 flows and 44
honeypot events. Hydra reuses connections across its tasks, so the flow count is lower than the
24 guesses and its tolerance is wider.
