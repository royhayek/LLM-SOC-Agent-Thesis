# F3 — Port scan (`port_scan`)

Ticket E1-10 (SCRUM-104). Method: ADR-0003. Predicted visibility (`attack_families.yaml`):
mqtt no, flows yes, honeypot yes.

## What it does

An external attacker host runs a TCP connect scan (`nmap -sT -n -T4`) against the honeypot over
a fixed port set (`22,23,80,443,1883,2323,8080,8883,9001`, honeypot's 22 included). The scan
runs in the `attacker` container and addresses the honeypot by IP. A connect scan completes the
TCP handshake, so Cowrie records a session on port 22 — a SYN-only scan would not, and the
honeypot cell would be wrong (ADR-0003 prediction risk). Bounded by the port set, so it exits 0.

## Testbed preconditions added for this family

- An `attacker` service (Debian bookworm, nmap/hydra/hping3/tcpreplay pinned per ADR-0003) on
  the isolated network at 10.77.0.30, idle until an episode drives it, with its own capture
  sidecar. The E1-01 isolation gate passes with it present (checked by the F3 slow test).
- The honeypot (Cowrie) now listens on port 22 (`COWRIE_SSH_LISTEN_ENDPOINTS`, plus a sysctl so
  the non-root cowrie user may bind 22), realising ADR-0003's `hp-ssh-01:22`. Default Cowrie
  listens on 2222, which left the honeypot cell empty.

Raw counts over two same-seed runs are compared within the F3 tolerance in
`tests/attack_tolerance.yaml` (flows 0.25, honeypot 0.40). Both runs gave 9 flows and 2 honeypot
events. The honeypot count is small, so its tolerance is wider.
