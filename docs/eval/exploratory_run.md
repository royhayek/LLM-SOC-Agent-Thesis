## Bugs found and fixed

The exploratory run surfaced, in order:
1. **Native crash on model load** (OpenMP/threading on 16 GB): KB model loaded once in the main thread + `TOKENIZERS_PARALLELISM`/`OMP_NUM_THREADS` (PR #95, #97).
2. **One bad output aborted the whole run**: the runner absorbs per-item failures as unusable verdicts (PR #95, #98).
3. **Output truncated at the 250-token ceiling** (visible reasoning under json_object): ceiling → 768 (METHODS changelog 19, PR #94).
4. **Dominant failure: JSON wrapped in markdown/code fences**: parse by JSON extraction (METHODS changelog 20, PR #101) — recovered C5 96.8%→1.6%, Baseline B 93.5%→4.8%.
5. **Benign verdicts failed the min-1 `evidence_ids` rule on sparse sources** (diagnosed from the per-bundle reason detail: C2 benign 4/31, C4 benign 0/31 ok): evidence required only for active actions (METHODS changelog 21, PR #104) — C2 benign 4→19, C4 benign 0→11 ok; the benign/attack validity is now balanced within each condition.

Residual (real, not a pipeline bug): single sparse-source conditions stay higher (C4 honeypot ~60%, inherent — no benign traffic reaches the honeypot, METHODS §8), and a small, roughly-uniform `node1_parse` (model emits 4+ `source_findings`) across all conditions. These are reported, not tuned.
