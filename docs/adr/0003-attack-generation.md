# ADR-0003: Attack generation method per family

- Status: Accepted (2026-10-04)
- Date: 2026-10-04
- Ticket: SCRUM-39 [E1-04]

## Context

Record §5 rules out custom attack code: attacks are generated by replaying published
datasets or by standard tooling. Fixing the method per family makes the scenarios citable
and reproducible and gives the ethics section (E11-06) its facts.

The six families are frozen by E1-02 (`knowledge/attack_families.yaml`, tag `families-v1.0`,
METHODS.md Changelog entry 1). That entry records the subject device and the predicted
visibility of each family, and leaves two preconditions to this ADR:

1. **Capture point.** The visibility matrix assumes flow capture sees all traffic on the
   testbed network. The current testbed (ADR-0008, Annex F ASSUMPTION 3) captures on the
   broker's network namespace only, so it would see no flows for the honeypot families,
   `syn_flood` or `botnet`. E1-02 states: if this ADR keeps the broker namespace, the frozen
   file is revised through a changelog entry before any attack traffic exists.
2. **Broker authentication.** `mqtt_brute_force` needs authentication enabled on the broker.
   The benign testbed broker runs with `allow_anonymous true` (`testbed/broker/mosquitto.conf`).

Tool versions and licences below were read on 2026-10-04 from each project and from the
Debian bookworm package index (the testbed sidecar image is `debian bookworm`-based,
ADR-0008). Dataset attack lists were checked by E1-02 and are cited there.

Criteria. Each family's method must: (C1) replay a published dataset or use standard tooling,
with no custom exploit code (§5); (C2) target the subject device that `attack_families.yaml`
records, with any replayed traffic retargeted to testbed device IDs so §4.1 keying works;
(C3) produce exactly the sources `attack_families.yaml` predicts; (C4) carry an open-source
licence that allows academic use; (C5) run inside the isolated testbed against testbed hosts
only.

## Decision

### Capture point

**Flow capture observes all traffic on the testbed network, not the broker namespace alone.**
This keeps the E1-02 visibility matrix valid (every family predicts `flows: yes`), so no
changelog entry against `families-v1.0` is needed. It supersedes Annex F ASSUMPTION 3 and
**amends ADR-0008**, whose tcpdump capture point (`-i eth0` on the broker's namespace) must
move to a point that sees honeypot, device-to-device and device-to-external traffic. The
concrete capture mechanism is an engineering change to the capture sidecar; this ADR fixes
the requirement, and the mechanism is settled in an ADR-0008 amendment before any attack
traffic is captured (leftover work, new ticket per DoD).

### Broker authentication

**The broker enables authentication for the corpus runs:** `allow_anonymous false` and a
`password_file` listing each testbed device's credentials. `mqtt_brute_force` guesses against
this. This changes `testbed/broker/mosquitto.conf` and the emulator connection settings; the
change is made by the family-implementation ticket (E1-11) and the benign profiles (E1-05)
reconnect with valid credentials. This ADR fixes the requirement only.

### Attacker host

External-origin families (`ssh_brute_force`, `port_scan`, `syn_flood`) are driven from an
**attacker container** attached to the testbed network, playing the role of an external host.
It has no route off the internal network (the isolation check of E0-07 still passes). Families
whose subject is a compromised device (`mqtt_publish_flood`, `mqtt_brute_force`, `botnet`) are
driven from that device's own namespace so the traffic keys to device D (Annex C).

### Method per family

No family uses custom exploit code. Live tools are run at fixed, low-rate parameters against
testbed hosts; `botnet` replays a published capture, retargeted. Expected sources match
`attack_families.yaml` exactly (`{mqtt, flows, honeypot}`).

| Family | Method (tool / dataset, version, licence) | Subject device D | Fixed parameters | Expected sources |
|---|---|---|---|---|
| `ssh_brute_force` | THC-Hydra, Debian bookworm `hydra` 9.4-1 (AGPL-3.0), SSH module, from the attacker container against the honeypot | honeypot `hp-ssh-01` (10.77.0.10:22) | one fixed username list and one fixed password list, both committed under `scenarios/`; fixed task count (`-t`) and one pass; completes the TCP handshake, so Cowrie logs sessions | flows, honeypot |
| `port_scan` | Nmap, Debian bookworm `nmap` 7.93+dfsg1-1 (NPSL, based on GPL-2.0), **TCP connect scan `-sT`**, from the attacker container against the honeypot | honeypot `hp-ssh-01` (10.77.0.10) | `-sT` (connect, not SYN, so the handshake completes and Cowrie records a session), fixed port set, fixed timing template | flows, honeypot |
| `mqtt_publish_flood` | `mosquitto_pub` loop, Debian bookworm `mosquitto-clients` 2.0.11 (EPL-2.0 / EDL-1.0), from the compromised device over one connection | IoT device D | one connection; fixed PUBLISH count, interval and payload size; fixed topic | mqtt, flows |
| `mqtt_brute_force` | `mosquitto_pub` repeated CONNECT with a credential list, `mosquitto-clients` 2.0.11 (EPL-2.0 / EDL-1.0), from the compromised device against the authenticated broker | IoT device D | one fixed credential list committed under `scenarios/`; fixed attempt rate; needs broker authentication (above) | mqtt, flows |
| `syn_flood` | hping3, Debian bookworm `hping3` 3.a2.ds2-10 (GPL-2.0), `--syn --flood`, from the attacker container against device D directly (not through the broker) | IoT device D | `--syn --flood`, fixed destination port, fixed duration; stopped by wall-clock, not packet count | flows |
| `botnet` | **Replay** of Mirai botnet traffic from CICIoT2023 [8] (first choice) or Bot-IoT [6], retargeted with `tcprewrite` and replayed with `tcpreplay`, Debian bookworm `tcpreplay` 4.4.3-1 (GPL-3.0+) | IoT device D (the bot) | source rewritten to D's IP/MAC, destination rewritten to a fixed non-routable external IP that no testbed host answers; fixed replay rate; a fixed slice of the source capture committed as a manifest, not the capture itself | flows |

Retargeting applies only to `botnet` (the one replayed family); the tool-generated families
are run live against testbed IPs and need none. `tcpreplay` and `tcprewrite` are the only tools
added beyond ADR-0002/ADR-0008 that touch the capture path; the attack tools (`hydra`, `nmap`,
`hping3`, `mosquitto-clients`) run in the attacker container and are not linked into `thesis`.

### Dataset licences and derived captures

The thesis **does not redistribute derived captures**. For `botnet` it commits a manifest
(dataset, file, byte range, SHA-256, retargeting map), not the replayed packets, and cites the
dataset. This sidesteps any redistribution restriction in the CICIoT2023 and Bot-IoT terms,
whose exact redistribution clauses were not read in full (**UNVERIFIED**); the manifest-only
decision holds regardless of what they allow. The published datasets are intrusion-detection
captures of synthetic/testbed traffic and are not represented as containing personal data.

### Ethics

All attack traffic runs inside the emulated testbed on its isolated internal Docker network
(10.77.0.0/24), which publishes no ports and whose isolation from the host LAN and the internet
is checked before any attack tooling runs (E0-07). No attack targets any third-party host: the
targets are testbed containers, and the `botnet` family's destination is a fixed non-routable
address that no real host answers. No family uses custom exploit code; attacks replay published
research datasets or run standard tools at fixed, low-rate parameters. No personal data is
collected or processed: telemetry is synthetic and the replayed datasets are not represented as
containing personal data. The agent only recommends and never executes; no code path acts on the
testbed or any network.

## Alternatives considered

| Option | For | Against |
|---|---|---|
| Keep capture on the broker namespace (ADR-0008 as-is) | No testbed change | Honeypot families, `syn_flood` and `botnet` would have no flows; breaks the frozen matrix; forces a `families-v1.0` changelog entry |
| Replay a captured dataset for every family (not just `botnet`) | One method for all; strong provenance | Retargeting six captures to testbed IDs and timings is brittle (original IPs, MACs, timings); live tools are simpler, standard and citable; most datasets' MQTT/SSH captures do not map onto Cowrie/Mosquitto cleanly |
| Generate every family with live tools (no replay at all) | No dataset licence question | No standard, reproducible "botnet" tool exists without custom C2 code, which §5 forbids; replay is the only no-custom-code route for `botnet` |
| SYN scan (`-sS`) for `port_scan` | Faster, stealthier (the usual default) | Never completes the handshake, so Cowrie logs nothing and the honeypot cell would be `no`, contradicting the frozen matrix (E1-02 `prediction_risk`) |
| Leave broker authentication off and target an unauthenticated CONNECT for `mqtt_brute_force` | No testbed change | There is nothing to guess; the family would not be a credential attack |

## Consequences

- Flow capture must see the whole testbed network. **ADR-0008 is amended** (capture point)
  before any attack traffic is captured; the capture-sidecar mechanism is a new engineering
  ticket. Annex F ASSUMPTION 3 is superseded.
- The broker runs authenticated for corpus runs. `testbed/broker/mosquitto.conf`, the emulators
  (E1-05) and `mqtt_brute_force` (E1-11) are affected; those changes belong to their tickets.
- An isolated attacker container is added to the testbed for the external-origin families; the
  E0-07 isolation check must still pass with it present.
- New tools recorded by this ADR: `hydra` 9.4-1, `nmap` 7.93+dfsg1-1, `hping3` 3.a2.ds2-10,
  `mosquitto-clients` 2.0.11 (already in the testbed image), `tcpreplay` 4.4.3-1. Pinned at the
  Debian bookworm versions above.
- Ruled out: custom attack or C2 code; a SYN scan for `port_scan`; redistributing derived
  captures; any target outside the isolated testbed.
- Implementing the families (E1-08 to E1-13) is out of scope for this ADR; it fixes the method,
  source, parameters, target and expected sources that those tickets build to.
